# 텐가이 횡스크롤 슈팅 — 설계 문서

- 작성일: 2026-09-21
- 상태: 승인됨 (사용자가 "장르까지 교체 — 횡스크롤 슈팅" + "텐가이 사례 기반 새 스프라이트" 선택)
- **대체 대상**: `2026-09-21-clawd-jump-design.md` (플랫포머). 그 문서는 폐기되었고 본 문서가 유효하다.
- 남은 시간 예산: 약 1시간 (2시간 중 약 55분 소진)

## 1. 목표

원작 **텐가이**(戦国ブレード / *Sengoku Blade: Sengoku Ace Episode II*, Psikyo, 1996)의
장르와 세계관을 재현한 단일 파일 횡스크롤 슈팅.

## 2. 원작 조사 결과 (설계 근거)

웹 검색으로 확인한 사실. 설계 결정은 모두 이 표에서 파생된다.

| 항목 | 원작 |
|---|---|
| 장르 | **횡스크롤 슈팅**. 전작(전국 에이스, 1993)은 종스크롤이었고 속편에서 횡으로 전환 |
| 조작 주체 | **"flying-person shooter"** — 비행기를 조종하지 않고 캐릭터가 맨몸으로 난다 |
| 세계관 | 전국시대 일본의 환상 버전. 요괴·마법 + **증기 기관 로봇** |
| 원작 해상도 | 320×224, 가로, 59.30 Hz |
| 조작계 | 8방향 + **버튼 2개 (FIRE, SPECIAL)** |
| 차지 | **발사 버튼을 누르고 있으면 차지** → 사역마 공격 |
| 사역마 | 파워업으로 획득·강화. 텐가이는 **매**, 차지하면 **봉황**이 되어 돌진 |
| 피격 규칙 | **적과 접촉 = 파워 레벨 1 하락(기절)**, **적 탄 피격 = 즉사** |
| 봄 | 희귀하고 화면 clear 위력이 약함. 아껴 쓰면 점수 보너스 |
| 주인공 | 텐가이(승병). 주 무장은 **신도 염주**, 봄은 **거대한 한자가 전방으로 흐름** |
| 스테이지 | 1~4면 무작위 순서 → 5면 중간보스 연속전 → 분기 → **최종보스는 제한 시간**, 늦으면 배드 엔딩 |
| 기술적 호평 | **패럴랙스 스크롤** |

### 범위에서 제외 (시간 예산)

1~4면 무작위 순서, 중간보스 연속전, 분기 경로, 2인 플레이, 캐릭터 셀렉트,
사운드, 컨티뉴, 난이도/라이프 설정 화면. **1스테이지 + 보스**로 축약한다.

## 3. 유지되는 것 / 폐기되는 것

**유지** (Task 1에서 이미 구현·커밋됨, `07d4708`):
논리 해상도 640×360, 정수 배율 스케일링, `image-rendering: pixelated`,
`ctx.imageSmoothingEnabled = false`, **고정 타임스텝 누산기**(`STEP = 1/60`,
`MAX_FRAME = STEP*5`), `window.__dbg()` 검증 훅, 단일 파일 `frontend/index.html`,
CDK S3 + CloudFront OAC 배포 설계.

**폐기**: 중력, 점프, 코요테 타임, 점프 버퍼, 타일 AABB 충돌, 타일 문자열 맵,
추적 카메라, 가시, 깃발, 코인 배치, `CLAWD` 12×8 배열.

> 해상도는 원작의 320×224 대신 **640×360을 유지**한다. 사용자의 원래 명시 제약이고
> Task 1이 이미 그 위에 구현되었다. 16:9 와이드는 횡스크롤 슈팅에 오히려 유리하다.

문자 그대로 사프란 주황색이다.

| 키 | 색 | 용도 |
|---|---|---|
| `D` | `#14130F` | 외곽선 (모든 스프라이트) |
| `S` | `#E8C9A0` | 피부 |
| `R` | `#D97757` | 승복 (사프란) |
| `B` | `#8C4A32` | 승복 그림자 |
| `G` | `#E8C468` | 금 — 염주 탄, 봉황, 아이템 |
| `A` | `#C4863A` | 매 깃털 |
| `P` | `#7A4A8C` | 요괴 살 |
| `M` | `#6B7280` | 증기 금속 |
| `C` | `#6FA88A` | 기계 눈, 적 탄 |

화면 색: 하늘 `#1A1917`, 원산 실루엣 `#2A2724`, 성벽 `#3A3631`,
성벽 상단 `#544E46`, 적 탄 `#C4463A`, HUD `#E8E2D8`,
오버레이 `rgba(20,19,15,0.75)`.

## 5. 스프라이트 (전부 기계 검증 통과)

셀 3px. 행 길이 일치 및 팔레트 문자 유효성을 검증했다.

| 이름 | 셀 | 픽셀 | 사용 색 |
|---|---|---|---|
| `MONK` 텐가이 | 12×12 | 36×36 | `B D G R S` |
| `HAWK` 사역마 매 | 7×5 | 21×15 | `A D` |
| `ONI` 요괴 | 8×8 | 24×24 | `D P` |
| `KARAKURI` 증기 로봇 | 10×8 | 30×24 | `C D M` |

보스는 배열이 아니라 `fillRect` 조합으로 절차적으로 그린다 (크기가 커서
배열로 관리할 이득이 없다).

## 6. 플레이어

| 항목 | 값 | 근거 |
|---|---|---|
| 스프라이트 | 36×36 | `MONK` 12×12 × 3px |
| **히트박스** | **8×8, 스프라이트 중앙** | 슈팅의 핵심 원칙 — 아래 참조 |
| 이동 | 8방향, 관성 없음, `150 px/s` | Psikyo 계열의 즉각 반응 |
| 화면 클램프 | `x ∈ [0, W-36]`, `y ∈ [0, H-36]` | |
| 라이프 | 3 | |
| 봄 | 2 | 원작대로 희귀 |
| 파워 레벨 | 1 ~ 4 | |

> **히트박스를 스프라이트의 1/20 크기로 두는 것이 슈팅 장르의 규칙이다.**
> 플랫포머에서는 보이는 것과 부딪히는 것이 일치해야 예측 가능하지만(이전 설계의
> 36×24 전체 박스), 슈팅에서는 탄막 사이를 통과하는 것이 게임의 본질이므로
> 히트박스가 작아야 "스칠 듯 피했다"가 성립한다. 같은 프로젝트에서 장르가
> 바뀌면 히트박스 철학도 반대로 뒤집힌다.

## 7. 무장

| 무장 | 값 |
|---|---|
| 염주 탄 | 4×4, `420 px/s` 우향, 발사 간격 `0.11s`, 파워 레벨 P → P개 스트림 (y 오프셋 `(i - (P-1)/2) * 9`) |
| 차지 | FIRE 홀드 시 누적, `CHARGE_FULL = 0.6s`. 만충 후 놓으면 봉황 발사 |
| 봉황 | 24×12, `560 px/s`, **관통**, 데미지 8 |
| 봄 (卍) | 화면의 **적 탄 전부 제거** + 화면 내 모든 적에게 데미지 30. 0.5s간 한자 스윕 렌더 |
| 적 탄 | 5×5, `190 px/s`, 발사 시점의 플레이어 위치로 조준 |

차지 중에도 염주는 정상 발사된다 (홀드 시 발사가 멈추면 조작감이 나쁘다).

## 8. 적

| 적 | 픽셀 | HP | 이동 | 발사 | 점수 |
|---|---|---|---|---|---|
| `ONI` 요괴 | 24×24 | 3 | 좌향 `90 px/s` + 사인 진폭 28px | 1.4s 간격 조준탄 1발 | 100 |
| `KARAKURI` 증기 로봇 | 30×24 | 8 | 좌향 `60 px/s` | 1.8s 간격 3방향 확산 | 300 |

## 9. 피격 규칙 (원작 충실)

| 사건 | 결과 |
|---|---|
| **적 본체와 접촉** | 파워 레벨 **-1** (최소 1), 무적 `0.8s`. **죽지 않는다** |
| **적 탄 피격** | 라이프 **-1**, 좌측 중앙 리스폰, 무적 `1.5s` |
| 라이프 0 | `GAMEOVER` |

이 비대칭이 원작의 특징이다. 몸통 박치기는 페널티일 뿐이고 죽음은 탄에서만 온다.

## 10. 보스

증기 카라쿠리 대형기. 절차적 렌더.

- HP 120, HP 바 표시
- **페이즈 1** (HP > 60): 1.2s 간격 3방향 확산
- **페이즈 2** (HP ≤ 60): 0.8s 간격 5방향 부채 + 좌향 돌진 후 복귀
- **제한 시간 45초.** 시간 내 격파 → `CLEAR`. 초과 → `BADEND`
- 점수 5000, 남은 봄 1개당 1000 보너스

제한 시간과 배드 엔딩은 원작 최종보스의 특징을 그대로 가져온 것이다.

## 11. 배경 (패럴랙스)

원작이 호평받은 요소. 3층, 절차적 도형.

| 층 | 내용 | 속도 배율 |
|---|---|---|
| 원경 | 산 실루엣 `#2A2724` | 0.25 |
| 중경 | 성벽 + 기와 `#3A3631` / 상단 `#544E46` | 0.6 |
| 근경 | 지면 띠 | 1.0 |

기준 스크롤 속도 `40 px/s`. 각 층은 모듈러 오프셋으로 무한 반복한다.

## 12. 조작

| 키 | 동작 |
|---|---|
| `ArrowLeft/Right/Up/Down` | 8방향 이동 |
| `KeyZ` 또는 `Space` | FIRE (홀드 = 차지) |
| `KeyX` | SPECIAL (봄) |
| `KeyR` | 재시작 |

원작의 2버튼 구성을 그대로 따른다. `Space`는 사용자의 원래 요구사항에 있던 키라
FIRE 별칭으로 남긴다.

## 13. 상태

`PLAYING` | `CLEAR` | `BADEND` | `GAMEOVER`. `R`은 어느 상태에서나 전체 리셋.

## 14. HUD

좌상단 `SCORE`, `LIFE`, `BOMB`, `POWER`. 보스 등장 시 상단에 HP 바와 남은 시간.

## 15. 검증

단위 테스트 없음(사용자 제약 유지). `/tmp/cj/verify.js` 하니스 재사용.

> **포트 8000을 쓴다.** 8080은 이 머신의 IDE 프로세스(PID 27549)가 상시 점유하고
> 있음을 확인했다. Task 1에서 하니스를 8000으로 변경했고 이후 전부 8000이다.

`window.__dbg()`는 `steps, state, score, lives, bombs, power, charge, px, py,
enemies, ebullets, pbullets, waveIdx, bossHp, bossTimer` 를 노출한다.
`window.__tp(x, y)` 는 플레이어를 놓고, `window.__skipTo(sec)` 는 웨이브 시계를
앞으로 돌려 보스 구간을 헤드리스로 검증할 수 있게 한다.

## 16. 배포

이전 설계의 §15를 그대로 유지한다: 비공개 S3 버킷 + CloudFront OAC +
`BucketDeployment`. CDK API 4개는 설치된 `aws-cdk-lib` 2.270.0에서 실측 확인했다.

## 17. 이름

게임 표시 제목은 **"TENGAI — 戦国"**. 레포·CDK 스택 이름(`clawd-jump`,
`ClawdJumpStack`)은 바꾸지 않는다 — 인프라 리소스 이름 변경은 스택 교체를
유발하고 남은 예산에 맞지 않는다.
