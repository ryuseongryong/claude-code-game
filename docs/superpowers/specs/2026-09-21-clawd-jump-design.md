## 1. 목표

순수 HTML5 Canvas + vanilla JavaScript로 만든 단일 파일 2D 플랫포머 게임.
주인공 Clawd가 타일 기반 레벨을 좌우로 진행하며 코인을 모으고, 가시를 피해
깃발에 도달하면 클리어한다. 최종적으로 AWS S3 + CloudFront에 정적 호스팅으로
배포한다.

### 범위에 포함

- `frontend/index.html` 단일 파일 게임 (외부 라이브러리 0개)
- CDK(TypeScript)로 S3 + CloudFront 배포 스택 작성 및 **실제 배포 수행**

### 범위에서 제외 (YAGNI)

- 단위 테스트 (시간 제약상 생략, 각 Phase는 브라우저 플레이로 검증)
- 가변 점프 높이 (Space를 짧게 떼면 낮게 점프) — 요구사항에 없음
- 사운드, 애니메이션 프레임, 적 캐릭터, 다중 레벨, 점수 저장
- Amazon Bedrock 등 AI 서비스 (이 게임은 사용하지 않음)
- 모바일 터치 입력

## 4. 게임 파일 내부 구조

`frontend/index.html`은 단일 IIFE 안에서 아래 순서로 블록을 배치한다. 파일이
하나라는 제약 안에서도 각 블록은 한 가지 책임만 가지며, 블록 간 통신은 명시적인
상태 객체(`player`, `cam`, `level`, `game`)를 통해서만 이루어진다.

1. 상수 / 설정 (해상도, 타일, 물리 상수)
2. Clawd 스프라이트 데이터 + 오프스크린 프리렌더
3. 레벨 맵 문자열 + 파서
4. 입력 처리
5. 플레이어 물리 업데이트
6. 타일 충돌 해석
7. 카메라
8. 엔티티 (코인 / 가시 / 깃발 / 시작점)
9. 렌더링 (타일, 엔티티, 플레이어, HUD, CLEAR 오버레이)
10. 게임 루프 (rAF + 고정 타임스텝 누산기)

## 5. 캔버스 & 스케일링

- 캔버스 backing store는 `640×360` 고정. 게임 로직은 항상 이 좌표계에서만 동작.
- JS가 창 크기에 맞는 **정수 배율**을 계산해 `style.width/height`를 설정한다:
  `scale = max(1, floor(min(innerWidth / 640, innerHeight / 360)))`
- 소수 배율을 쓰면 `pixelated` 필터 하에서도 일부 논리 픽셀이 2px, 일부가 3px로
  찍혀 스프라이트 두께가 불규칙해진다. 정수 배율이 모든 논리 픽셀의 크기를
  동일하게 보장한다.
- `ctx.imageSmoothingEnabled = false`를 설정한다.
- `resize` 이벤트에서 배율을 재계산한다.

## 6. Clawd 스프라이트

```js
const CLAWD = [
  ".AAAAAAAAAA.",
  ".AAAAAAAAAA.",
  ".AABAAAABAA.",
  "AAAAAAAAAAAA",
  "AAAAAAAAAAAA",
  ".AAAAAAAAAA.",
  "..A.A..A.A..",
  "..A.A..A.A..",
];
const PALETTE = { A: "#D97757", B: "#14130F" };
```

- 12열 × 8행, 셀 3px → **36 × 24 px**
- `.`은 투명, 그 외 문자는 `PALETTE`에서 색을 조회
- 시작 시 **36×24 오프스크린 캔버스 2장**에 한 번만 굽는다: 정방향 1장,
  좌우 반전 1장. 이후 렌더는 `drawImage` 한 번.
  - 매 프레임 96개 `fillRect`를 호출하지 않아 렌더 비용이 상수가 된다.
  - `ctx.scale(-1, 1)`을 매 프레임 쓰지 않아 변환 행렬 저장/복원 비용과
    반올림 오차가 사라진다.
- `facing`은 `vx`의 부호가 바뀔 때만 갱신. `vx === 0`이면 마지막 방향 유지.
- 렌더 좌표는 `Math.round(player.x - cam.x)`, `Math.round(player.y)`로 정수 스냅.

### 게임 전체 색상 팔레트

요구사항의 `PALETTE`는 Clawd 전용이다. 나머지 요소의 색은 Clawd의 주색
`#D97757`(따뜻한 주황)과 `#14130F`(거의 검정)에서 파생시켜 화면 전체가 하나의
팔레트로 읽히게 한다.

| 요소 | 색 | 의도 |
|---|---|---|
| 배경 (하늘) | `#1A1917` | `#14130F`보다 살짝 밝게 — 어두운 배경에서 주황 Clawd가 또렷하다 |
| 지형 타일 `X` 본체 | `#3A3631` | 배경과 구분되지만 전경을 압도하지 않는 중간 톤 |
| 지형 타일 상단 1px 하이라이트 | `#544E46` | 밟을 수 있는 면을 시각적으로 명시 |
| 코인 `C` | `#E8C468` | 노란 금색 — Clawd 주황과 색상환에서 인접해 조화롭되 구분된다 |
| 가시 `^` | `#C4463A` | 붉은색 — 위험의 관습적 신호. Clawd 주황보다 채도가 높고 어둡다 |
| 깃발 `F` 깃대 | `#544E46` | 지형 하이라이트와 동일 — 구조물로 읽힌다 |
| 깃발 `F` 천 | `#6FA88A` | 녹색 — 화면의 유일한 녹색이라 목표로 눈에 띈다 |
| HUD 텍스트 | `#E8E2D8` | 오프화이트 |
| CLEAR 오버레이 | `rgba(20, 19, 15, 0.75)` | `#14130F` 기반 반투명 |

형태 규칙: 지형은 16×16 꽉 찬 사각형 + 상단 1px 하이라이트. 코인은 타일 중앙
8×8 사각형(회전/애니메이션 없음). 가시는 타일 하단에 3개의 위로 향한 삼각형
(`moveTo`/`lineTo` 3회). 깃발은 2px 폭 깃대 + 상단에 8×6 삼각형 천.

## 7. 물리

### 고정 타임스텝 누산기

`requestAnimationFrame`은 가변 dt를 제공한다. 이를 물리에 직접 쓰면 (a) 프레임이
튈 때 점프 높이가 달라지고, (b) 한 프레임 이동량이 타일 크기(16px)를 넘으면
터널링이 발생한다.

```
STEP = 1 / 60
acc += min(dt, MAX_FRAME)          // MAX_FRAME = 5 * STEP
while (acc >= STEP) { step(STEP); acc -= STEP }
render()                            // rAF당 1회
```

`acc`를 최대 5스텝으로 클램프해 탭 전환 후 복귀 시 "죽음의 나선"(따라잡으려
수백 스텝을 돌다 더 느려지는 현상)을 막는다.

### 물리 상수

| 상수 | 값 | 근거 |
|---|---|---|
| `TILE` | 16 px | 요구사항 |
| 플레이어 히트박스 | 36 × 24 px | 스프라이트 전체 박스 = 히트박스 |
| `MOVE_SPEED` | 130 px/s | 화면 폭(640px)을 약 4.9초에 횡단 |
| `GRAVITY` | 1300 px/s² | |
| `JUMP_V` | 380 px/s | 최고점 = 380² / (2 × 1300) ≈ **55 px ≈ 3.4 타일** |
| `MAX_FALL` | 560 px/s | 스텝당 9.3 px < 16 px → 터널링 불가 |
| `COYOTE_TIME` | 0.1 s | 요구사항 |
| `JUMP_BUFFER` | 0.1 s | 요구사항 |

### 도출되는 레벨 디자인 제약

- 체공 시간 = 2 × (380 / 1300) ≈ **0.585 s**
- 체공 중 수평 도달 거리 = 0.585 × 130 ≈ **76 px ≈ 4.7 타일**
- ⇒ **안전한 최대 수평 간격: 4타일**
- ⇒ **안전한 최대 상승 단차: 3타일**

### 코요테 타임 / 점프 버퍼

초 단위 카운트다운 타이머 2개로 구현한다.

- 접지 상태면 `coyote = COYOTE_TIME`, 아니면 매 스텝 `coyote -= STEP`
- Space `keydown`(최초 누름) 시 `buffer = JUMP_BUFFER`, 매 스텝 `buffer -= STEP`
- `buffer > 0 && coyote > 0` → `vy = -JUMP_V` 후 **`buffer = 0; coyote = 0`**

> 점프 실행 후 두 타이머를 모두 0으로 리셋하는 것이 필수다. 리셋을 누락하면
> 한 번의 입력으로 공중에서 두 번 점프된다.

`coyote`는 "지면을 떠난 직후 늦게 누른 입력"을, `buffer`는 "착지 직전 미리 누른
입력"을 구제한다. 둘 다 프레임 수가 아니라 초 단위여야 프레임 레이트와 무관하게
동일한 느낌이 유지된다.

## 8. 충돌 해석 (축 분리 AABB)

한 스텝 안에서 축을 분리해 **X를 먼저, 그다음 Y를** 처리한다.

```
1. x += vx * dt
   겹치는 solid 타일 검사 → X축으로만 밀어냄, vx = 0
2. y += vy * dt
   겹치는 solid 타일 검사 → Y축으로만 밀어냄
     - 아래로 이동 중이었다면: onGround = true, vy = 0
     - 위로 이동 중이었다면:   vy = 0 (천장)
```

- Y를 먼저 처리하면 벽에 붙어 낙하할 때 벽에 걸려 멈추는 아티팩트가 생긴다.
- 두 축을 동시에 해결하려 하면 "어느 축으로 밀어낼지" 모호해진다. 축 분리는
  그 모호성 자체를 제거한다.
- 타일 조회 범위: `floor(x / 16)` ~ `floor((x + w - 1) / 16)`.
  `x + w`를 그대로 쓰면 AABB가 정확히 타일 경계에 닿았을 때 인접 타일까지
  포함해 벽에 밀착할 수 없게 된다. **`w - 1`을 쓸 것.**
- 레벨 경계 처리:
  - **좌 / 우 바깥**: solid로 취급해 레벨 밖으로 나가지 못하게 한다.
  - **아래 바깥**: solid가 아니며 낙사 판정 대상이다 (§10).
  - **위 바깥**: solid가 아니다 (천장 없음). 대신 레벨 디자인으로 제약한다 —
    §9의 상단 여백 규칙 참조.

## 9. 레벨

### 형식

문자열 배열. **100열 × 22행** = 1600 × 352 px (화면 약 2.5개 폭).

| 문자 | 의미 |
|---|---|
| `X` | 지형 (유일한 solid) |
| `C` | 코인 |
| `^` | 가시 |
| `F` | 깃발 (골) |
| `S` | 시작점 |
| `.` | 빈칸 (공백 문자도 빈칸으로 허용) |

> **가정 명시**: 원 요구사항의 범례에는 시작점 문자가 없으나 "가시에 닿으면
> 시작점 리스폰" 기능에 시작 좌표가 필요하다. 범례를 최소로 확장해 `S`를
> 추가한다. 맵에 `S`가 없으면 기본 좌표로 폴백한다.

### 파싱

로드 시 **1회만** 수행한다.

- `X`만 `solid` 불린 그리드(`Uint8Array` 또는 2차원 배열)에 기록
- `C` / `^` / `F` / `S`는 solid 그리드에서 제외하고 **엔티티 배열**로 변환

이렇게 하면 렌더 루프에서 문자 비교를 하지 않고, 코인 획득 시 맵 문자열을
변형하는 부작용도 없다. 리셋은 엔티티 배열을 다시 만들기만 하면 된다.

### 엔티티 히트박스

| 엔티티 | 히트박스 (타일 좌상단 기준) |
|---|---|
| 코인 | 중앙 10 × 10 (`+3, +3`) — 넉넉하게 획득 |
| 가시 | 하단 12 × 8 (`+2, +8`) — 위를 스쳐도 죽지 않음 |
| 깃발 | 타일 전체 16 × 16 |

위험 요소는 스프라이트보다 히트박스를 **작게**, 보상은 **크게** 만든다.
플레이어는 "아슬아슬하게 살았다"를 실력으로 기억하고 "억울하게 죽었다"를
버그로 기억하기 때문이다.

### 레벨 구성 (좌 → 우, 난이도 상승)

1. 시작 평지 + 코인 3개 (튜토리얼)
2. 2~3타일 수평 간격 점프
3. 가시 열 뛰어넘기
4. 3타일 단차 계단 상승
5. 공중 발판 위 코인
6. 4타일 폭 가시 구덩이
7. 최종 발판에 깃발

코인 총 **12개**. 모든 세로 통로는 **최소 3타일 폭** (§11 참조).

### 상단 여백 규칙

위쪽 경계에는 천장이 없으므로(§8) 점프로 화면 위를 벗어날 수 있다. 카메라가
`cam.y = 0` 고정이라 화면을 벗어나면 Clawd가 보이지 않는다.

점프 최고점이 55 px, 스프라이트 높이가 24 px이므로, 행 `r`의 발판 위에 선
Clawd의 최고점은 `16r - 24 - 55 = 16r - 79`이다. 이것이 0 이상이려면
`r ≥ 4.94`.

⇒ **밟을 수 있는 발판은 행 5 이상에만 배치한다.** 행 0~4는 비워 둔다.

## 10. 게임 상태

상태는 `PLAYING`과 `CLEAR` 두 가지.

| 이벤트 | 결과 |
|---|---|
| 가시 히트박스 접촉 | 시작점 리스폰 (코인 획득 상태 **유지**) |
| 레벨 바닥 아래로 낙하 (`y > levelH + 64`) | 시작점 리스폰 (코인 유지) |
| 깃발 히트박스 접촉 | `CLEAR` 상태 전이 |
| `R` 키 | 언제든 전체 리셋 (코인 포함, `PLAYING`으로) |

리스폰 시 코인을 유지하는 이유: 리스폰 페널티가 없어 시간 제약 하의 플레이
테스트가 빠르다. 리스폰은 위치와 속도만 초기화한다.

`CLEAR` 상태에서는 물리 업데이트를 멈추고 반투명 어두운 오버레이 위에
`CLEAR!`, 코인 수, `PRESS R`을 표시한다.

## 11. 히트박스와 타일 크기의 상호작용

Clawd 히트박스는 **36 px 폭 = 2.25 타일**이다. 이는 레벨 디자인에 직접적인
제약을 만든다.

- 폭 2타일(32 px) 통로에는 물리적으로 들어갈 수 없다.
  ⇒ **모든 세로 통로는 최소 3타일(48 px) 폭**이어야 한다.
- 높이는 24 px(1.5 타일)이므로 2타일 높이 공간은 여유롭게 통과한다.

히트박스를 스프라이트보다 작게 인셋하지 않고 전체 36×24를 쓰는 이유: 픽셀아트
스케일에서 보이는 것과 충돌하는 것이 일치해야 플레이어가 충돌을 예측할 수 있다.

## 12. 카메라

레벨 높이 22행 = 352 px ≈ 캔버스 높이 360 px이므로 **수직 스크롤이 불필요**하다.
`cam.y = 0` 고정, X축만 추적한다.

```
cam.x = Math.round(clamp(player.cx - 320, 0, levelW - 640))   // levelW - 640 = 960
```

`Math.round`가 필수다. 카메라가 소수 좌표를 가지면 모든 타일이 서브픽셀 위치에
그려져 픽셀아트가 흐려지고 스크롤 중 떨림이 보인다.

즉시 추적(lerp 없음)을 채택한다. 부드러운 추적은 폴리시이며 리스크가 없는
즉시 추적을 기본으로 한다.

### 타일 렌더링 범위

화면에 보이는 열만 그린다:
`c0 = floor(cam.x / 16)` ~ `c1 = ceil((cam.x + 640) / 16)`.

100열 전체를 그려도 성능 문제는 없지만, 컬링 범위 계산은 두 줄이고 레벨을
넓히더라도 렌더 비용이 일정하게 유지된다.

## 13. 입력

- `window`의 `keydown` / `keyup`에서 `Set`으로 눌린 키를 추적
- `ArrowLeft`, `ArrowRight`, `Space`는 `preventDefault()` — Space는 페이지를
  스크롤시키고 화살표도 스크롤을 유발한다
- 점프는 `keydown`의 **최초 누름**(`event.repeat` 무시)에서만 `buffer`를 설정한다
- `R`은 `keydown`에서 즉시 리셋

## 14. HUD

- 좌상단에 `COINS n/N` 표시. **`N`은 하드코딩하지 않고 맵 파싱 시 센 `C`의
  개수**를 쓴다. 레벨을 수정해도 HUD가 자동으로 맞는다.
- 렌더는 `drawText(text, x, y)` 함수로 감싼다. 초기 구현은
  `ctx.font = '8px monospace'` + `fillText`.
- 3배 확대 시 약간 부드럽게 보이지만 2시간 예산을 지키는 선택이다.
- 시간이 남으면 3×5 비트맵 폰트로 교체한다. `drawText` 하나만 바꾸면 되도록
  호출부를 캡슐화해 둔다.

## 15. Phase 4 — AWS 배포

### 스택 구성 (`lib/clawd-jump-stack.ts`)

| 리소스 | 설정 |
|---|---|
| S3 Bucket | `blockPublicAccess: BLOCK_ALL`, `encryption: S3_MANAGED`, `removalPolicy: DESTROY`, `autoDeleteObjects: true` |
| CloudFront Distribution | origin: `S3BucketOrigin.withOriginAccessControl(bucket)`, `defaultRootObject: 'index.html'`, `viewerProtocolPolicy: REDIRECT_TO_HTTPS`, `priceClass: PRICE_CLASS_100` |
| BucketDeployment | `Source.asset('frontend')`, `distribution` + `distributionPaths: ['/*']` |
| CfnOutput | 배포 URL (`https://<distributionDomainName>`) |

`bin/clawd-jump.ts`의 `env`를 `CDK_DEFAULT_ACCOUNT` / `CDK_DEFAULT_REGION`으로
활성화한다.

### 왜 OAC + 비공개 버킷인가

S3 정적 웹사이트 호스팅 엔드포인트는 HTTP만 지원하고 버킷을 공개해야 한다.
OAC(Origin Access Control)는 CloudFront만 버킷을 읽을 수 있는 서명된 요청을
사용하므로 버킷을 완전 비공개로 유지하면서 HTTPS, HTTP/2, 엣지 캐싱을 얻는다.
`S3BucketOrigin.withOriginAccessControl()`이 OAC 리소스와 버킷 정책을 자동
생성한다. 구식 OAI보다 권장되는 방식이다.

`removalPolicy: DESTROY` + `autoDeleteObjects`는 실습 프로젝트의 정리 편의를
위한 선택이며, 프로덕션에서는 쓰지 않는다.

### 주의 사항

- CloudFront 배포 **생성**은 5~10분 소요된다. 이후 콘텐츠 갱신은
  `BucketDeployment`의 무효화로 수 초 내 반영된다.
- 구현 시 `aws-core:aws-cdk` 스킬을 참조해 `aws-cdk-lib` 2.270.0의 정확한 API를
  확인한다 (기억에 의존하지 않는다).
- `BucketDeployment`의 소스는 평범한 디렉터리 asset이므로 로컬에서 zip되며
  Docker가 필요하지 않다.

## 16. 구현 순서와 검증 게이트

단위 테스트는 생략하고 각 Phase를 브라우저 플레이로 검증한다. 검증은 2단계로
수행한다.

1. 로컬 HTTP 서버를 띄우고 헤드리스 Chrome(Chrome DevTools MCP)으로 접속 →
   콘솔 에러 0 확인 → 키 입력 스크립트 실행 → 스크린샷 → 결과 보고
2. 사용자가 직접 플레이할 접속 방법(포트 포워딩 등)을 안내 → 피드백 수령 후
   다음 Phase 진행

| Phase | 내용 | 통과 기준 |
|---|---|---|
| 1 | 엔진: 루프, 입력, 물리, Clawd 렌더 | Clawd가 정확한 픽셀 형태로 그려지고, 좌우 이동·점프·중력 낙하가 동작한다 |
| | ↳ Phase 1에는 레벨 시스템이 없으므로 **임시 지면**(`y = 344`의 수평선 하나)을 두어 중력·점프·코요테 타임을 검증한다. Phase 2에서 타일 충돌로 대체된다. | |
| 2 | 레벨, 충돌, 카메라 | 타일이 그려지고 지형을 관통하지 않으며, 카메라가 Clawd를 따라 레벨 경계에서 clamp된다 |
| 3 | 코인, 가시, 깃발, HUD | 코인 카운트가 증가하고, 가시 접촉 시 시작점 리스폰, 깃발 도달 시 CLEAR, R로 재시작된다 |
| 4 | CDK로 S3 + CloudFront 배포 | `cdk deploy` 성공 후 CloudFront URL에서 게임이 정상 동작한다 |

## 17. 확정된 판단 사항

설계 검토 시 승인된, 원 요구사항 범위 안에서 내린 판단:

1. 레벨 범례에 시작점 문자 `S`를 최소 확장으로 추가한다.
2. 히트박스는 스프라이트 전체 36×24를 사용하고, 그에 맞춰 세로 통로를 최소
   3타일 폭으로 설계한다.
3. HUD는 `fillText`로 시작하고, 비트맵 폰트는 시간이 남을 때의 폴리시로 둔다.
